1. 30초 요약 (엘리베이터 피치)

한 문장 요약
"VisRAG 공개 벤치마크 위에서, 동일한 generator(Qwen2-VL-7B + NF4)와 동일한 oracle 페이지를 사용하여 evidence 형식(이미지 단독 / 파싱 텍스트 단독 / 결합)이 정확도에 미치는 영향만을 격리해서 측정한 ablation 연구."

핵심 결과 (외워둘 숫자)

  • Baseline (image_only) macro 0.229 → PV-RAG macro 0.592, +36.32%p
  • MP-DocVQA에서 PV-RAG가 parsed_text_only 대비 +4.0%p 추가 이득 (0.800 vs 0.760) — 이미지 + 파싱의 상보성을 보여주는 가장 강한 증거
  • ChartQA만 역방향: parsed_text_only 0.524 > parsed_visual 0.508 (자연스러운 발견)
  • 총 실행시간 6,331초 (~1시간 45분), RTX 4060 8GB 단일 GPU

왜 중요한가

VisRAG 논문의 가정은 "OCR/파싱 없이 이미지만으로 검색·생성하는 것이 더 우월하다"이다. 본 연구는 동일 데이터·동일 generator에서 파싱을 더하면 오히려 크게 좋아진다는 것을 보여주며, 특히 레이아웃이 답에 기여하는 문서에서는 이미지 + 파싱 결합이 둘 중 어느 단독보다도 우월함을 입증.

2. 꼭 외워야 하는 핵심 개념 5가지

① VisRAG

OpenBMB가 제안 (arXiv:2410.10594). 페이지 이미지를 시각 임베딩으로 검색(VisRAG-Ret) → VLM(MiniCPM-V 2.6 / GPT-4o)이 이미지에서 직접 답 생성. OCR/파싱 단계의 정보 손실(레이아웃, 색상, 그래픽)을 회피하는 것이 동기.

② PV-RAG (우리 방법)

Parsed-Visual RAG. Upstage Document Parse로 페이지 이미지를 텍스트·표로 추출한 뒤 원본 이미지와 함께 동일 VLM에 입력. 가설: "파싱은 정확한 라벨·수치를, 이미지는 레이아웃을 보존하므로 두 증거가 상보적이다."

③ Oracle 검색 (--oracle)

실제 검색을 안 하고 qrels의 정답 페이지를 직접 generator에 공급. 모든 모드가 같은 페이지에서 답을 생성하므로 정확도 차이는 오직 evidence 형식에서 비롯. generation-only ablation의 핵심 장치.

④ NF4 양자화 (bitsandbytes)

Qwen2-VL-7B를 4-bit NormalFloat로 적재 (≈6GB VRAM). bf16(~14GB)이 8GB GPU에 안 들어가서 채택. 일반적으로 정확도 -5~10%p. 세 모드에 동일 적용되므로 모드 간 Δ는 공정 비교.

⑤ Relaxed Exact Match

VisRAG 논문과 동일한 지표. 공백 정규화 + 소문자 + substring containment + 숫자는 5% 상대 오차까지 정답 인정. 코드: benchmark/metrics.py:16-44.

+ Upstage Document Parse

한국 Upstage AI의 문서 파싱 API. 페이지 이미지에서 평문 / 표 마크다운 / 표 설명을 추출. 본 실험에서 4 데이터셋 248 페이지 파싱 (USD 3~5).

4. 시스템 아키텍처 (4단계 파이프라인)

(A) Upstage parse  : corpus 페이지 이미지 → 텍스트·표 cache (JSONL)
(B) 페이지 선택     : --oracle → qrels gold corpus-id 직접 선택
(C) Generation     : (이미지 ± 파싱 evidence) → Qwen2-VL-7B → 답변
(D) 평가 & 표출    : relaxed exact match → PPT slide-10 양식 결과 표

각 단계는 독립적으로 캐시되고 재실행 가능. scripts/run_today_ppt_pipeline.sh가 4단계를 일괄 실행하며, 결과 파일이 존재하면 자동 skip.

ParsedDocument 스키마 (parse cache)

ParsedDocument(
    dataset:            str,             # e.g., "MP-DocVQA"
    corpus_id:          str,             # e.g., "txpp0227_p9.jpg"
    text:               str,             # plain text content
    tables_markdown:    list[str],       # markdown-rendered tables
    table_descriptions: list[str],       # short caption of each table
    parse_status:       str,             # "ok" | "failed"
    error:              str,             # populated on parse failure
    raw_upstage:        dict[str, Any]   # raw API response (audit)
)

JSONL의 한 줄 = 한 페이지. cache_key(dataset, corpus_id)로 조회. evidence_text(doc)가 텍스트·표·표설명을 세 섹션 헤더로 직렬화하여 prompt에 삽입.

해석 4줄

① 전반적 효과: 모든 4 데이터셋에서 PV-RAG가 image_only baseline을 크게 상회. macro +36.32%p는 양자화 잡음·표본 변동으로 설명 불가.

② MP-DocVQA 우위: parsed_visual이 parsed_text_only를 +4.0%p (0.800 vs 0.760) 상회. 다중 페이지 문서에서 "어느 표의 어느 행" 같은 위치 정보를 이미지가 보완. PV-RAG가 OCR-only 대비 추가 가치 있음을 보이는 가장 직접적 증거.

③ ChartQA 역방향: parsed_text_only(0.524) > parsed_visual(0.508). Upstage가 차트 수치를 잘 추출한 경우 텍스트만으로 충분하고, 이미지 추가시 약간의 혼동 발생. "OCR이 충분히 강하면 시각 추가의 한계 수익은 작거나 음수"라는 자연스러운 발견.

④ 동률 (InfoVQA, SlideVQA): InfoVQA는 max_pixels 캡이 가장 강하게 작용하여 이미지 정보 밀도 감소. SlideVQA는 슬라이드가 큰 글씨 중심이라 파싱이 거의 모든 정보 보존.

실행 통계

  • 총 generation call: 363 query × 3 mode ≈ 1,089 calls (ChartQA 63 + 나머지 100 × 3)
  • 총 실행 시간: 6,331초 (~1시간 45분)
  • 최장 단일 mode: InfoVQA × parsed_visual ≈ 65분 (큰 infographics + 결합 evidence)
  • 최단 단일 mode: ChartQA × image_only ≈ 1분
  • GPU 점유: 최대 7.9 / 8.0 GB, 평균 utilisation 80~100%
  • Upstage parse 비용: 248 페이지, 추정 USD 3~5

7. 왜 이렇게 설계했나 (정당화)

7.1 왜 Qwen2-VL-7B인가? (논문은 MiniCPM-V인데)

  1. 1차 목적은 팀 사전 자료 (PPT slide-10)의 baseline 행에 우리 방법론을 추가하여 같은 좌표계에서 Δ를 보고하는 것. 팀이 Qwen2-VL-7B를 썼으므로 우리도 동일 family로 정렬.
  2. VisRAG 논문 자체가 "시각 검색 > 텍스트 RAG"라는 결론은 generator 변경에 강건하다고 보고. 우리 가설은 generator 강도가 아니라 evidence 형식의 영향 → generator 차이의 결론 영향은 제한적.
  3. MiniCPM-V 2.6 cross-check는 후속 작업으로 분리.

7.2 왜 NF4 양자화 + 해상도 캡?

단일 RTX 4060 8GB VRAM이라 Qwen2-VL-7B bf16(~14GB)이 안 들어감.

  • bitsandbytes NF4 4-bit: 일반적으로 -5~10%p 정확도 손실. VRAM ~6GB로 감소.
  • max_pixels = 1.3M 캡: Qwen2-VL은 28×28 픽셀을 1 vision token으로 변환. 캡 없으면 큰 infographic이 7,800+ token, 캡 적용시 ~1,700 token (메모리·시간 ~1/20).
핵심 framing: 두 조치는 세 모드에 동일하게 적용되므로 모드 간 Δ는 공정 비교. 절대값이 팀 사전 자료의 풀 정밀 baseline보다 낮은 것은 예상된 영향. 발표에서는 항상 "constrained-environment delta"로 framing.

7.3 왜 oracle 검색을 썼나? (--oracle)

  1. 실험 격리: 통제 변수는 evidence 입력 형식. 실제 검색을 쓰면 모드별 검색기 선택 차이가 evidence 효과와 혼동.
  2. 컴퓨팅 제약: VisRAG-Ret 시각 임베딩 검색은 공식 demo가 약 40 GB GPU 요구. 8GB 환경에서 실행 불가능.
  3. 학술적 관례: VisRAG 논문도 generation ablation을 위해 oracle/동일 검색 결과를 공급하는 비교를 분리하여 보고.

→ 본 보고서가 측정하는 것은 end-to-end 정확도가 아니라 generation-isolated 정확도. 발표에서 명시적으로 진술 필수.

7.4 왜 100개 표본?

  • 시간 제약: 단일 GPU 풀 평가는 15~30시간 추정.
  • 통계적 충분성: 표본 100은 5%p 차이를 95% 신뢰도로 구분 가능 (이항 표준오차 √(0.5·0.5/100) = 0.05).
  • 관찰 Δ는 +14~+58%p로 표본 변동을 크게 상회.
  • 선택 방식: 무작위 아닌 HF dataset의 수록 순서대로 첫 N개 → 재현성과 외부 cross-check 보장.

9. 예상 질문 & 답변

설계 의도 관련

왜 VisRAG 논문의 6개가 아니라 4개 데이터셋만 사용했나?
팀 사전 자료(PPT slide-10)의 결과 표 컬럼이 InfoVQA, ChartQA, DocVQA, SlideVQA의 4개로 구성되어 있어서 같은 양식에 직접 행을 추가하기 위함. ArxivQA, PlotQA는 후속 작업으로 분리. 4개만으로도 macro Δ +36.32%p가 통계적으로 충분히 유의미.
왜 MiniCPM-V 2.6이 아니라 Qwen2-VL-7B를 generator로 썼나? 논문 재현이 아닌가?
본 연구는 "논문 재현"이 아니라 "팀 사전 자료의 baseline 행에 PV-RAG 행을 추가하는 ablation"이다. 팀 PPT가 Qwen2-VL-7B로 측정되어 있어 baseline의 좌표계를 일치시키려면 동일 generator로 정렬할 수밖에 없다. 또한 VisRAG 논문 자체가 결론이 generator에 강건하다고 보고한다. MiniCPM-V 2.6 cross-check는 ≥16GB GPU에서의 후속 작업으로 §11에 명시.
Oracle 검색을 쓰면 실제 시스템에서는 의미가 없는 것 아닌가?
맞다. 본 보고서가 측정하는 것은 end-to-end 정확도가 아니라 generation-isolated 정확도이다. 통제 변수가 evidence 형식이므로 모든 모드가 같은 정답 페이지에서 답하도록 oracle을 사용한다. 이는 VisRAG 논문도 generation ablation에서 동일하게 사용하는 학술적 관례. 또한 VisRAG-Ret 시각 검색은 40GB GPU 요구로 8GB 환경에서는 물리적으로 실행 불가능. 검색 비교는 retrieval 보고로 분리.
NF4 양자화로 정확도가 떨어지는데 결론이 의미 있나?
두 가지로 답한다. ① NF4는 세 모드에 동일하게 적용되므로 모드 간 Δ는 공정 비교. 절대값이 풀 정밀보다 낮은 것은 예상된 영향. ② 본 연구는 "절대 SOTA 갱신"이 아니라 "constrained-environment delta"로 framing. macro +36.32%p는 양자화 잡음(보통 -5~10%p)을 훨씬 상회하므로 결론을 흔들지 못함.

방법론 관련

parsed_visual이 parsed_text_only를 항상 이기지 못한 이유는?
데이터셋별로 다르다. ① MP-DocVQA (+4.0%p): 다중 페이지 문서에서 위치·레이아웃 정보가 답에 기여 → 이미지가 보완. ② ChartQA (-1.6%p): Upstage가 차트 수치를 잘 추출한 경우 텍스트만으로 답 가능 → 이미지 추가시 약간 혼동. ③ InfoVQA, SlideVQA (동률): InfoVQA는 max_pixels 캡 영향이 가장 커서 이미지 정보 밀도 감소. SlideVQA는 큰 글씨 중심이라 파싱이 거의 모든 정보 보존. → "이미지+파싱 결합의 한계 이득은 데이터셋의 시각 정보 의존도에 비례"가 본 결과의 함의.
왜 첫 100개를 무작위가 아니라 순서대로 뽑았나? 편향 위험 없나?
재현성과 외부 cross-check 가능성을 보장하기 위함. HF dataset의 수록 순서대로 첫 N개를 쓰면 누구나 동일한 표본을 얻을 수 있다. 무작위 표본은 seed 공유가 안 되면 비교 불가. 표본 100개에서 관찰된 Δ가 +14~+58%p로 표본 표준오차(±5%p)를 크게 상회하므로 표본 선택 방식이 결론을 뒤집을 가능성은 매우 낮다.
Upstage Document Parse 대신 PaddleOCR이나 Tesseract를 안 쓴 이유는?
Upstage는 평문뿐 아니라 표를 markdown으로 보존하고 표 설명(caption)도 추출한다. 일반 OCR은 표를 평문 줄로 펼쳐서 행·열 구조가 손실된다. 본 실험에서 MP-DocVQA·InfoVQA처럼 표가 답에 기여하는 데이터셋에서는 구조 보존이 큰 차이를 만든다. 비용 측면에서도 248 페이지 ~USD 3-5로 무시할 수준.
왜 top-k = 1만 평가했나? 논문은 1, 2, 3 곡선도 보고하는데.
Oracle 모드는 정의상 정답 페이지가 이미 결정되므로 top-k = 1이 자연. 실제 검색의 top-k 곡선은 retrieval 비교(VisRAG-Ret vs BM25)와 묶여 별도 retrieval 보고에서 다룰 영역. §11에 한계로 명시.

구현/숫자 관련

max_pixels = 1.3M은 어떻게 정했나?
Qwen2-VL은 28×28 픽셀을 1 vision token으로 변환한다. 1,310,720 / (28×28) ≈ 1,670 token이 한 이미지의 상한이 되어 prompt + answer + 이미지 토큰을 4096 context window에 안전히 담을 수 있는 값이다. 캡 없으면 큰 infographic이 7,800+ token으로 모델 한계를 넘는다. 메모리·시간은 약 1/20로 감소.
왜 max_new_tokens = 32인가? 너무 짧지 않나?
VisRAG 평가셋의 답변이 대부분 짧은 답(숫자·짧은 구) 형식이고, 상한을 늘리면 모델이 부연설명을 붙여 relaxed EM에서 오답으로 판정되는 경우가 생긴다. 32 token이 답변 길이와 noise 차단을 동시에 만족하는 값. 세 모드에 동일 적용되므로 공정 비교에 영향 없음.
do_sample = False(그리디)인 이유는?
재현성. 그리디 디코딩은 동일 입력에 항상 동일 출력을 보장하므로 ablation의 모드 간 비교가 noise 없이 깨끗해진다. Sampling을 쓰면 seed에 따른 변동이 evidence 형식 효과와 섞임.
총 1시간 45분이라는데, 풀 평가는 얼마나 걸리나?
표본 100 → 풀 평가(InfoVQA 718, MP-DocVQA 591, SlideVQA 556)로 scaling하면 약 15~30시간 추정. ChartQA만 풀(63)이라 추가 작업은 InfoVQA·MP-DocVQA·SlideVQA에 집중됨. 본 연구는 시간 제약과 통계적 충분성을 근거로 표본 평가를 선택.

한계/방어 관련

결과가 ablation 한 변수(evidence 형식)에만 한정되는데, 실제 시스템 효과는?
맞다. 실제 시스템에서는 검색 정확도·답변 정렬·후처리가 함께 작용한다. 본 보고서는 그 중 generation 단계의 evidence 형식 효과만 격리. end-to-end 효과는 후속 retrieval 보고와 합쳐 평가될 예정. Ablation 자체가 "전체 시스템 보장이 아닌 컴포넌트 효과 입증"이라는 점이 명시적 framing.
PV-RAG가 OCR-only 시스템 대비 가지는 추가 가치를 한 줄로 말한다면?
"파싱 텍스트는 정확한 라벨·수치를 보장하지만 페이지 내 위치·레이아웃 정보를 잃는다. 원본 이미지를 함께 입력하면 이 손실을 보완할 수 있으며, MP-DocVQA에서 관찰된 +4.0%p가 이를 직접 입증한다."
Upstage 파싱이 실패한 페이지는 어떻게 처리했나?
ParsedDocument에 parse_status("ok"/"failed")와 error 필드가 보관되며, 실패 페이지는 evidence_text가 빈 문자열을 반환. parsed_text_only 모드에서 답이 안 나올 수 있고, parsed_visual은 이미지에 의존. 본 실험 248개 페이지는 모두 ok 상태로 확인.

10. 한계와 후속 작업

  1. Generator paper-alignment 미실시: Qwen2-VL-7B + NF4에 한정. MiniCPM-V 2.6 cross-check는 ≥16GB GPU 필요.
  2. Retrieval 비교 미실시: oracle 사용. VisRAG-Ret(시각) vs BM25(파싱 텍스트) 검색 비교는 별도 retrieval 보고로 분리. BM25는 본 코드베이스에 이미 구현됨.
  3. 표본 크기: 데이터셋당 첫 100 (ChartQA 63)은 5%p Δ 검출에 충분하나, 데이터셋 내 부분 분포 효과 분석엔 풀 평가 필요.
  4. 이미지 해상도 캡 영향: max_pixels 1.3M은 8GB GPU 제약 결과. 풀 해상도에선 특히 ChartQA·InfoVQA 결과가 달라질 가능성.
  5. Top-k = 1 고정: VisRAG 논문은 1, 2, 3 곡선 보고. 본 보고서는 oracle top-k = 1로 한정.
  6. Generator scaling 부재: 팀 PPT Table 2 (Qwen2-VL-72B, InternVL2.5-78B, Qwen2.5-VL-72B)는 본 보고서 범위 밖. DashScope·OpenRouter·cloud GPU로 보완 가능.

  1. "본 연구는 VisRAG 논문 재현이 아니라 같은 데이터·지표 위에서의 generation-only ablation이다."
  2. "NF4·해상도 캡은 세 모드에 동일 적용되므로 모드 간 Δ가 fair comparison이고, 절대값은 constrained-environment 수치이다."
  3. "MP-DocVQA의 +4.0%p가 이미지·파싱 증거의 상보성을 직접 입증하는 가장 강한 신호이다."

  • 표본 100개: "5%p Δ를 95% 신뢰도로 구분 가능. 관찰 Δ는 +14~+58%p로 표본 표준오차의 3~10배."
